Sticky Markers 0.7 beta focuses on note safety, responsiveness, and resource limits.

We completed a security review and a multi-lane code review, with independent frontend, backend, and security reviewers. This was a manual source and runtime review; the official Codex Security scan runner was unavailable. This release addresses all 11 actionable findings from that review.

- Rendered table edits reach the saved document immediately. Save, rename, close, and quit include active cell input.
- Older disk polls cannot replace newer edits or successful saves.
- Concurrent create, rename, and vault moves use a consistent lock order; autosave request locks have a fixed upper bound.
- Malformed attachment URLs show an error in the affected preview, and rendering failures are isolated so the rest of the app remains usable.
- Local attachment previews load when visible, with bounded file reads, image decoding, dimensions, concurrency, and transfer size. Raster attachments use static thumbnails; supported SVG previews use bounded static shapes, text, and gradients.
- GitHub sync compares hashes and stages changed files incrementally instead of retaining several complete vault copies. Aggregate size, file count, and response limits prevent runaway allocations.
- Cursor movement in dense rendered Markdown updates the affected lines instead of rebuilding the whole note.
- Updated KaTeX throughout the math/diagram dependency tree to address GHSA-238p-pmpm-9mq7. The production npm advisory check reports zero known advisories.
- Window placement saves are coalesced on a worker, preserving current note settings without blocking the native event thread.
- Saving preferences preserves newer settings changed in other notes. An explicit GitHub vault selector exposes the correct sync and conflict controls for every managed vault.

The previously reported whole-system freeze was not reproduced. Testing did not establish a persistent RAM leak; these fixes address confirmed failure paths and reduce resource pressure without claiming a proven cause for that incident.

Packages: Linux x86_64 RPM, DEB, and AppImage; Arch PKGBUILD/Makefile; Windows x64 EXE; macOS Intel and Apple Silicon DMG; source archive, signatures, and SHA256 checksums. Flatpak remains deferred. Update checks link to release packages for installation using your existing package format.

## Fix verification

The review findings were addressed at their shared runtime boundaries, rather than only in the reported examples.

| Finding | Change and regression evidence |
| --- | --- |
| R1: rendered table input loss | Every cell edit updates the document; the native-input barrier runs before Save/Rename/Close/Quit. Browser tests save and rename a focused cell without blur, close a second edited cell, and capture pending native input. |
| R2: stale disk poll | Single-flight reads capture a document generation and saved revision; obsolete responses are discarded. A held old read is released after typing/saving, and another edit saves correctly. |
| R3: create/rename deadlock | Naming locks precede path locks, including cross-vault moves. OS-process tests verify lock ordering and concurrent completion; the regressions fail against the previous sources. |
| R4: attachment allocation | The native reader validates type before acquisition, limits the byte stream, bounds decoder metadata/output actual WebP headers and shared lossless tables, and serializes decoding. Visible-only frontend reads have a bounded queue. Fixtures exercise oversized files, compressed metadata, forged headers, output/pixel bounds and valid images. |
| R5: malformed URL/render failure | Shared image/link parsing contains invalid escapes; each Markdown renderer has an error boundary. Browser tests keep navigation/source editing available and recover after correcting a rendering fault. Encoded spaces and wiki filename delimiters remain supported. |
| R6: sync payload copies | Metadata-only indexes, sequential disk staging and explicit budgets cover sync, conflict resolution and API responses. Mock tests preserve conflicts/no-force updates, skip unchanged downloads and reject unsafe sizes before changes. |
| R7: dense note cursor latency | Ordered hidden ranges replace repeated scans; selection changes restore/reveal affected lines. A 72 KiB/8,000-span fixture checks untouched decorations and completes 30 cursor moves in about 3 ms in this environment. |
| R8: geometry saves on UI thread | Window identities map directly to a coalescing worker; geometry and appearance merge under the config lock. Tests retain current color/font/pin state and do not resurrect deleted note styles. |
| R9: request lock file growth | Saves share 64 persistent request-lock stripes. The 600-save regression bounds lock growth and retains the 512-receipt cap; old lock inodes remain untouched for safety. |
| R10: stale settings form | Only edited fields are patched under the config lock; immediately saved fields clear their dirty state. Tests preserve newer mode, toolbar pins, appearance and line-number settings from other notes. |
| R11: sync controls target wrong vault | Settings explicitly selects from all managed GitHub vaults. A fixture starts with an unmanaged active vault and switches between two managed vaults with different options. |

The original security paths were local/shared note data reaching an unbounded attachment reader, malformed image URLs reaching an uncaught React effect, and managed-vault payloads multiplying in memory during sync. The fixes keep filesystem access vault-relative, render invalid data as a local error, and impose bounds before acquiring/decoding payloads or applying sync changes. Legitimate UTF-8 files, URI filenames, valid images, conflict recovery, and non-force commits have control tests.

Preview compatibility limits are documented in the README: local raster previews are static thumbnails; WebP has a 4-megapixel cap; SVG supports a bounded static subset. The small [vendored WebP decoder patch](../../vendor/PATCHES.md) enforces a shared table budget because the upstream codec does not honor every allocation limit; its provenance and maintenance requirements are included. The full attachment files stay on disk. Live OAuth and macOS/Windows graphics profiling were not performed locally; native builds and Rust regressions run on all release platforms. The reported Fedora freeze remains unconfirmed.

Local verification on Linux passed: 61 Rust tests (`cargo test --locked --workspace`), 15 TypeScript unit tests (`npm test`), 47 browser workflows (`npm run test:e2e -- --workers=1`), five release-script tests, production build/type checks and Rust formatting. Native lifecycle smoke exercised the actual DEB payload; RPM/DEB executable, desktop-file and icon permissions passed. The production npm audit reported zero advisories. Release CI repeats Rust/unit checks on Linux, Windows, and both macOS architectures before attaching packages.

A repeated native test of the final 0.7 executable used 50 Markdown/JSON files and 20 Pinned/vault tab cycles: peak combined process RSS was 420.6 MiB and final idle RSS was 411.8 MiB. RSS includes the desktop and WebKit subprocesses and can double-count shared pages. This short test did not reproduce the reported freeze or establish an ongoing memory leak.
